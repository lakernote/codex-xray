# Codex X-Ray security and privacy review

## Executive summary

The repository, tracked files, documentation assets, and available Git history were checked for committed credentials, private keys, personal home paths, real WeChat identifiers, and private email addresses. No committed credential or project-specific personal identifier was found.

The review found three implementation issues and one documentation issue. All are fixed in the current working tree. The most important change removes conversation bodies, full patches, complete tool output, and unredacted credentials from the persistent Trace index; a database migration clears older Trace cache rows.

## Findings

### [PRIV-001] Persistent Trace index retained sensitive Session content

- **Severity:** Medium
- **Location:** `src-tauri/src/trace_analysis.rs:3576`, `src-tauri/src/trace_analysis.rs:4290`, `src-tauri/src/storage.rs:408`
- **Evidence:** Trace records previously serialized message bodies, complete tool results, patch content, and unredacted nested credential fields into the X-Ray SQLite index.
- **Impact:** This created an unnecessary second local copy of private Codex content. Although the application-data directory is user-only, the copy could persist in backups or survive after the original Session was removed.
- **Fix:** Tool arguments are now recursively bounded and redacted, patch bodies and complete tool results are omitted, message bodies are removed before persistence, and selected Session content is reloaded read-only into memory only when opened. Database schema version 5 clears older Trace cache rows.
- **Status:** Fixed.

### [PRIV-002] WeChat system messages could expose local paths and command credentials

- **Severity:** Medium
- **Location:** `src-tauri/src/remote_channel.rs:2565`, `src-tauri/src/remote_channel.rs:2834`, `src-tauri/src/remote_channel.rs:2895`, `src-tauri/src/remote_channel.rs:2929`
- **Evidence:** Task lists and status messages included full working directories, while progress and approval messages could include raw commands or error text.
- **Impact:** A home-directory username, project layout, token, password, authorization header, or API key embedded in a command could be sent to WeChat.
- **Fix:** Task messages now show only the final directory name. X-Ray-generated errors, progress, and approval summaries abbreviate home paths and redact common credential fields, flags, assignments, bearer tokens, and key-shaped values. Regression tests cover path and credential leakage.
- **Status:** Fixed.

### [REACT-XSS-001] QR SVG used an HTML injection sink

- **Severity:** Low
- **Location:** `src/RemoteControlView.tsx:422`
- **Evidence:** The QR SVG was rendered with `dangerouslySetInnerHTML`.
- **Impact:** The current SVG is generated by the Rust QR library, so no exploitable untrusted path was identified. Keeping an HTML injection sink would make future data-flow changes riskier.
- **Fix:** The SVG is encoded as a `data:image/svg+xml` image source and rendered with an ordinary `<img>` element.
- **Status:** Fixed.

### [DOC-001] Security and lifecycle documentation was inaccurate

- **Severity:** Low
- **Location:** `SECURITY.md:15`, `docs/data-sources.en.md:197`, `docs/data-sources.zh-CN.md:199`, `CHANGELOG.md:15`
- **Evidence:** Documentation referred to operating-system credential stores, claimed X-Ray did not proxy selected Chat traffic, and said the app remained in the system tray after closing.
- **Impact:** Users could make privacy and operational decisions using an incorrect data-flow description.
- **Fix:** English and Chinese documentation now describes user-only credential files, the optional loopback Chat bridge, the WeChat boundary, on-demand Session reads, and the actual close-to-exit lifecycle.
- **Status:** Fixed.

## Expected data boundaries

- Native Responses requests go directly from Codex to the selected provider. A Chat provider explicitly selected by the user receives that task's requests through X-Ray's loopback compatibility bridge.
- Enabling WeChat sends prompts, replies, progress, and approval summaries through WeChat. System-generated messages are sanitized, but model-generated replies can still contain information the user asked Codex to process.
- The WebView keeps recent aggregate UI state and identifiers in its local application profile for fast startup. This data is not telemetry and is protected by the user-only application-data directory.
- Same-task Codex Desktop control uses a private local IPC protocol. It is version-sensitive and fails closed when ownership or protocol validation fails.
